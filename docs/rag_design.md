# RAG 设计

## 总体架构

```text
用户问题
→ 意图识别
→ 查询改写
→ 多路检索
   → 向量检索：历史正文、讲解材料、论文摘要
   → 关键词检索：人名、地名、书名、事件
   → 结构化检索：景点、票价、开放时间、路线
   → 图谱检索：人物-事件-地点-文献关系
→ 证据重排
→ 回答生成
→ 引用来源与风险提示
```

## 知识类型

- person：人物
- event：事件
- place：地点
- text：文献
- comparison：正史/演义差异
- route：路线
- service：票务、开放时间、交通等服务信息

## Chunk 原则

不按固定字数硬切，按“可独立回答一个问题的知识单元”切。

一个 chunk 应该包含：

- 标题
- 正文
- 实体标签
- 来源
- 可信等级
- 适用人群
- 叙事阶段
- 风险提示

## 可信等级

- A：原典、官方资料、正式出版物、老师确认资料
- B：论文摘要、地方研究文章、景区展陈文本
- C：网络攻略、用户游记、未核实二手资料

生成回答时：

- A 可直接使用
- B 可使用但最好标注来源类型
- C 只能作为旅行体验参考，不能作为历史事实依据

## 禁止策略

- 不得编造票价、开放时间、演出时间。
- 不得把文学演义当作正史结论。
- 不得把地方品牌宣传直接写成学术定论。
- 不得在缺少资料时伪造出处。
